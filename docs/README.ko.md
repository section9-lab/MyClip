## 할 수 있는 일

- **작업을 되짚어 보세요.** 캡처 타임라인을 탐색하고 노트의 근거가 된 자료를 확인할 수 있습니다. 각 캡처에는 읽거나 복사하거나 열 수 있는 로컬 OCR 텍스트 문서가 있습니다.
- **개인 지식 라이브러리를 만드세요.** 프로젝트, 주제, 일상 작업에 걸쳐 노트를 검색하고 편집하고 연결할 수 있습니다. 노트는 Markdown 파일이므로 다른 편집기에서도 열 수 있습니다.
- **다음 할 일을 추적하세요.** 추천 작업을 검토하고 필요한 항목을 확정한 뒤 보드에서 진행 상황을 확인할 수 있습니다. **Kanban**과 **Reports** 사이를 전환해 프로젝트와 진행 상황별로 정리된 일간, 주간, 월간 업무 보고서를 볼 수 있습니다.
- **AI 도구에 맥락을 제공하세요.** Codex, Claude Code, Claude Desktop, Cursor, OpenCode에서 저장된 메모리를 검색하도록 할 수 있습니다.

## 시작하기

**macOS 13 이상**과 **Codex 또는 Claude 계정**이 필요합니다. 에이전트 커넥터를 설치하려면 **Node.js 22 이상**도 필요합니다. 로컬 빌드 방법은 아래에 있습니다.

1. MyClip을 열고 사이드바의 **Backstage**로 이동합니다. 커넥터를 설치하고 로그인한 뒤 **Connect**를 눌러 사용 가능한지 확인합니다. 이어서 **Enable**을 눌러 정리에 사용할 에이전트를 활성화합니다. 연결만으로 작업이 시작되지는 않습니다. 여러 에이전트에 연결할 수 있지만 한 번에 하나만 활성화할 수 있습니다.
2. **화면 기록**과 **손쉬운 사용** 권한을 허용합니다. MyClip이 열려 있는 동안 자동으로 캡처하며, 권한을 허용한 직후에도 시작됩니다.
3. 평소처럼 작업하면 됩니다. 기본적으로 포인터가 1초 동안 멈춘 뒤 클릭할 때, 세로 스크롤을 멈춘 지 2초가 지났을 때, 또는 영문자 키를 누른 뒤 Return을 누를 때 활성 창을 캡처합니다. 자동 정리는 새 캡처를 Memory로 정리합니다.
4. **Memory**에서 노트를, **Timeline**에서 캡처를, **Kanban**에서 추천 작업을 확인하세요.

AI 도구에서 메모리를 사용하려면 설정에서 **MyClip MCP**를 켜고 클라이언트를 선택한 다음 구성을 적용합니다. 이후 클라이언트를 다시 시작하거나 새 세션을 여세요.

**Claude Code(CLI)**는 ACP를 통해 백그라운드에서 캡처를 정리합니다. **Claude Desktop**에는 앱 열기와 Chat 및 로컬 Code 세션의 MCP 메모리 접근 설정을 위한 별도 항목이 있습니다. 백그라운드 정리용으로 활성화할 수는 없습니다. 데스크톱 설정은 `~/Library/Application Support/Claude/claude_desktop_config.json`에 저장되며, 기존 서버를 유지하고 CLI 설정은 변경하지 않습니다. 설정 후 Claude Desktop을 완전히 종료한 다음 다시 여세요.

## 캡처 텍스트 문서

MyClip은 Apple Vision으로 중국어와 영어 텍스트를 기기 안에서 추출하며, AI 정리와 독립적으로 작동합니다. 캡처 상세 화면에서 **OCR 文档**를 선택하면 텍스트를 읽거나 복사할 수 있습니다. **打开文档**를 선택하면 원본 이미지 옆에 저장된 UTF-8 `.txt` 파일을 엽니다. 반복된 캡처는 이미지와 텍스트 문서를 공유합니다. 읽을 수 있는 텍스트가 없는 캡처에는 빈 문서가 생성되며, 인식 실패는 다시 시도할 수 있습니다.

기존 캡처는 앱 시작 후 백그라운드에서 처리됩니다. OCR 문서와 검색 인덱스는 보관 설정에 따라 원본 이미지와 함께 만료됩니다. 저장된 Memory 노트는 유지됩니다. 앱은 macOS 27을 포함한 macOS 13 이상을 지원합니다. macOS 13에서는 단일 프레임 ScreenCaptureKit 스트림을 사용하며, 최신 시스템과 동일한 앱 제외 규칙을 적용합니다.

## 캡처 정리

캡처는 저장되는 즉시 영구 대기열에 들어갑니다. 자동 정리는 가장 오래된 대기 캡처부터 3분을 기다린 뒤 같은 에이전트를 위한 배치를 시간순으로 만듭니다. 한 배치는 최대 **이미지 8개와 OCR 레코드 32개**, OCR 텍스트 합계 **12,000자**까지 포함합니다. Return 및 수동 캡처는 이미지를 사용하고, 클릭·스크롤·이전 포인터 트리거의 캡처는 로컬 OCR을 사용합니다. 없는 OCR은 전송 전에 생성합니다. 비어 있거나 실패했거나 한 건의 길이가 너무 긴 OCR은 원본 이미지로 대체하며 이미지 수 제한에 포함합니다. 제한을 초과하게 되는 첫 레코드 앞에서 배치를 끝내며, 그 레코드를 건너뛰지 않습니다. 새 캡처가 추가되어도 타이머는 초기화되지 않습니다. 한 번에 한 배치만 실행하고, 배치 시작 사이에 최소 3분 간격을 둡니다.

**Backstage**에는 대기 수, 남은 시간, 현재 배치가 표시됩니다. **Organize Now**로 한 배치를 미리 시작할 수 있습니다. 실패하거나 중단되면 다시 시도하거나 재개할 때까지 자동 처리가 일시 중지됩니다. 캡처와 기존 Memory 파일은 보존됩니다. 입력 모드와 OCR 내용은 배치를 만들 때 고정되며, 재시도나 재시작 후에도 유지됩니다. 캡처 상세 화면의 **按图片重新整理**는 원본 이미지를 명시적으로 전송하므로 OCR이 보존하지 못하는 차트나 레이아웃에 유용합니다. 다른 에이전트를 활성화하면 자동 정리를 기다리는 캡처가 재할당됩니다. 실행 중인 배치는 기존 에이전트로 완료합니다. 기존 작업과 재시도도 원래 에이전트를 유지하며, 해당 에이전트가 다시 활성화될 때까지 기다립니다.

각 배치는 독립적인 임시 세션을 사용합니다. Claude에는 `persistSession: false`를 전달합니다. MyClip의 Codex app-server 프록시는 `ephemeral: true`를 강제하고, 이를 확인하지 않는 백엔드는 거부합니다. 각 실행이 끝나면 에이전트 프로세스를 닫습니다. 이전에 저장한 대화는 재개하거나 삭제하지 않습니다. 다음 배치에는 고정 정리 규칙, 직전에 성공한 배치의 인계 정보만 최대 4 KiB, 타임스탬프와 소스 ID가 포함된 현재 입력, 앱·창·트리거 메타데이터, 기존 작업 맥락을 전달합니다. 관련 Memory 파일은 필요할 때 읽습니다. 인계 정보는 저장된 파일 변경 사항과 소스 ID를 기록하되 대화 이력과 Memory 본문은 제외하며, Memory 게시에 성공한 뒤에만 교체합니다. 실패 후 재시도는 새 세션에서 시작하고 현재 파일을 확인합니다.

활성화된 에이전트가 없으면 캡처는 대기열에 남습니다. 에이전트를 비활성화하면 새 작업 배정은 중지하지만 진행 중인 작업은 마칠 수 있습니다. MyClip은 활성화한 에이전트를 기억하고 앱 시작 시 다시 연결합니다. 이전 버전의 기본 에이전트 설정만으로 자동 활성화되지는 않으므로 업그레이드 후에는 명시적으로 활성화해야 합니다.

MyClip은 모든 정리 및 작업 발견 세션을 **전체 접근 권한**으로 시작합니다. Codex에는 `agent-full-access`, Claude Code에는 `bypassPermissions`를 사용합니다. 파일 접근, 편집, 명령, 네트워크 접근, MCP 도구 호출은 작업마다 확인 카드를 띄우지 않고 진행합니다. 남은 도구 권한 요청도 활성 세션에서 자동 처리하지만, 취소된 작업은 늦게 도착한 요청을 거부합니다. 도구 활동은 실행 기록에서 계속 확인할 수 있습니다.

**Backstage**는 정리, 작업 발견, 재시도의 보고된 토큰 사용량을 에이전트별·배치별로 집계합니다. 각 요청이 끝날 때 사용량을 로컬에 저장하며, 오래되거나 보고되지 않은 값은 0이 아니라 확인 불가로 표시합니다. 컨텍스트 창 점유량은 소비량으로 계산하지 않습니다. 활성 배치는 현재 단계, 경과 시간, 마지막 진행 업데이트 이후 시간을 보여 줍니다. Claude ACP는 Claude Code의 기존 로그인과 네트워크 설정을 사용하므로, 구성된 로컬 프록시가 있다면 실행 중이어야 합니다.

현재 세션에서 새로운 추론, 응답 텍스트, 도구 활동 또는 권한 활동이 5분 동안 없으면 정리를 중단합니다. 진행이 있는 동안에는 계속 실행할 수 있지만 한 배치의 총 실행 시간은 15분을 넘지 않습니다. 사용량만 갱신되거나 다른 세션에서 활동이 발생해도 제한 시간은 연장되지 않습니다.

Memory는 캡처 관측 시각(`observed_at`)과 파일 갱신 시각(`updated_at`)을 구분합니다. Now는 근거가 캡처된 시각을 보여 주며, 오래된 근거가 더 최신의 Now 페이지를 덮어쓸 수 없습니다. 관측 시각이 없으면 알 수 없는 상태로 유지합니다. 정리기는 사건 이력을 Daily에 모으고, 결론은 프로젝트·주제 페이지에 저장하며, 해결된 항목을 Inbox에서 옮깁니다. 반복적이거나 우연한 탐색마다 영구 노트를 새로 만들 필요는 없습니다.

새로 정리된 페이지의 `source_ids`에는 본문에서 실제로 인용한 캡처 ID만 들어갑니다. 배치의 참고 캡처는 `context_source_ids`에 별도로 보관되며 모든 문장의 근거가 되는 것은 아닙니다. MCP 검색 결과에는 각 문단이 인용한 소스 ID가 포함되며, `memory_get`은 페이지 뒤에 있는 캡처를 요약합니다(개수, 기간, 앱). 기존 노트는 계속 읽을 수 있고 다시 정리할 때 이 규칙을 적용합니다. 업그레이드할 때 노트를 일괄 재작성하지 않습니다.

앱과 MCP의 메모리 검색은 동일한 SQLite FTS5 순위를 사용합니다. 키워드는 일부 검색어와 일치해도 검색되며, 정확히 일치하는 제목과 등록된 별칭을 가장 먼저, 그다음 각 노트에서 가장 잘 맞는 문단과 노트 전체 BM25를 함께, 마지막으로 파일 수정 시각을 고려합니다. 문단 단위로 점수를 매기면 긴 노트가 실제로 질문에 답하는 문단을 밀어내는 일을 막을 수 있습니다. 중국어와 문장 부호에는 리터럴 부분 문자열 검색도 사용할 수 있습니다. 빈 검색어는 최근 편집한 노트를 나열합니다.

MCP는 읽기 전용 도구 두 가지를 제공합니다. `memory_search`는 `query`(질문 또는 키워드)와 선택적으로 `since`, `until`, `app`, `limit`(기본값 10)을 받아, `path`, `title`, 짧은 `snippet`(최대 300자인 일치 문단 최대 2개), `time`, 문단이 인용한 `sourceIDs`, 출처 `apps`를 포함한 순위 결과를 반환합니다. `memory_get`은 이 결과의 `path`를 받아, 선택적으로 특정 섹션을 읽는 `#heading`과 줄 범위를 지정하는 `from`/`lines`를 받습니다. 반환값은 Markdown 줄, 제목별로 묶은 페이지의 링크, 최신순 역방향 링크(각각 링크가 있는 줄과 날짜 포함), 페이지 뒤에 있는 캡처 요약입니다. 알 수 없는 인자는 무시되지 않고 거부됩니다.

검색은 Wikilink를 따라갑니다. 가장 강한 일치 결과와, 질문에 맞는 줄을 가진 링크의 양쪽 끝이 씨앗이 되어 링크 그래프에서 2단계로 퍼져 나갑니다. 각 씨앗에서 한 홉, 그리고 엔티티 페이지(Daily 노트 → 인물 또는 주제 페이지 → 다른 Daily 노트)를 거칠 때만 두 번째 홉까지 확장합니다. 각 링크는 그 줄이 질문과 얼마나 일치하는지에 따라 가중치가 매겨지고, 도착하는 페이지가 가진 링크 수만큼 감쇠되므로 `Now.md`처럼 허브 역할을 하는 페이지가 결과를 뒤덮지 않습니다. 루트 파일과 `Wiki/Archives`는 제외됩니다. 이렇게 도달한 페이지는 직접 일치한 결과와 함께 순위가 매겨지며 `via`(한 홉 또는 두 홉, 각각 링크를 가진 페이지, 제목, 줄 자체, 날짜)를 포함합니다. 링크는 관련성을 나타낼 뿐, 사실 관계의 증거는 아닙니다.

`time`과 `since`/`until` 필터는 내용이 언제 일어났는지를 나타냅니다: 문단에 표시된 사건, 없으면 인용된 캡처, 그것도 없으면 파일 편집 시각 순입니다. `since`는 경계를 포함하고 `until`은 포함하지 않으며, 둘 다 ISO 8601 타임스탬프를 받습니다. `app`을 지정하면 사건이 있는 노트는 해당 앱의 캡처도 인용하는 사건 문단을 통해 일치하고, 사건이 없는 노트는 범위와 앱을 모두 만족하는 인용된 캡처가 하나 필요합니다. 날짜를 모르는 사건을 캡처나 편집 시각으로 대체하지 않습니다. 범위를 지정하지 않은 날짜 있는 페이지는 최근 날짜를 약간 더 우대합니다.

사건 주석은 해당 문단 바로 앞에 빈 줄 없이 HTML 주석으로 저장합니다. Markdown을 복사하거나 인덱스를 다시 만들어도 유지됩니다. 예:

```markdown
<!-- myclip-event {"start":"2026-09-10T00:00:00+08:00","end":"2026-09-11T00:00:00+08:00","precision":"day","evidence":"2026-09-10"} -->
2026-09-10에 고객 회의가 끝났다. 출처: 캡처 `REPLACE_WITH_ACTUAL_SOURCE_UUID`.
```

실제 근거와 실제로 인용한 캡처 ID를 사용하세요. 지원하는 정밀도는 `day`(현지 달력 날짜), `range`(끝 경계를 제외한 명시적 구간), `instant`(끝을 생략하거나 시작과 같은 시점)입니다. 타임스탬프에는 UTC 오프셋이 명시되어야 합니다. 검색은 결과의 `time`으로 사건 시작 시각을 반환합니다. 이는 노트의 주장을 기록하는 것이며, 출처를 독립적으로 검증했다는 뜻은 아닙니다. 잘못된 날짜, 충돌하는 주석, 코드 예제 안의 주석, 문단 인용 누락, 문단에 없는 `evidence` 표현은 사건 시간 인덱스를 만들지 않습니다. 상대 날짜를 해석하려면 원본 메시지의 시각과 시간대를 알아야 하며, 정리기는 원래 표현을 보존하고 변환 방식을 설명해야 합니다. 캡처나 편집 시각으로 빠진 사건 날짜를 채우지 않습니다. 기존 노트는 주석 없이도 검색할 수 있고, 관련 근거를 정리할 때 주석이 추가됩니다. 업그레이드가 날짜를 만들어 내거나 바꾸지는 않습니다.

문단, 사건, 링크 인덱스는 파생된 SQLite 데이터입니다. 편집 시 갱신하고 노트 삭제 시 함께 삭제하며, 오래된 라이브러리에서도 Markdown을 변경하지 않고 다시 만듭니다. 두 홉을 넘어서는 질문에는 에이전트가 `memory_get`으로 페이지를 읽고 거기 나열된 링크나 역방향 링크를 따라갑니다.

임시 세션은 Codex나 Claude에서 다시 열 수 없습니다. 대신 MyClip에서 실행 상세 정보를 확인하세요. 각 기록에는 입력 이미지와 텍스트 수가 함께 표시됩니다. 이 설정은 재개 가능한 로컬 에이전트 대화를 방지하지만, 모델 제공자의 서버 측 데이터 보관 정책을 결정하지는 않습니다.

**Backstage**에서 정리 기록을 누르면 재시도를 포함한 각 요청의 도구 호출, 명령 인자, 결과, 파일 위치와 편집, 에이전트 응답, 입력·출력 토큰, 캐시 읽기·쓰기, 보고된 비용을 확인할 수 있습니다. 도구 기록은 요청 실행 중 저장되며, 취소하거나 재시작한 뒤에도 남습니다. 비용은 보고된 세션 누적 금액의 차이로 계산하며, 보고가 없거나 기준 금액을 모르면 알 수 없는 상태로 유지합니다. 이전 기록의 토큰 합계는 보존하지만, 저장하지 않았던 도구 상세 정보는 복원할 수 없습니다.

## 개인정보 보호와 제어

- **무엇을 캡처할지 선택하세요.** 설정은 범위(기본값은 활성 창 또는 해당 창이 있는 디스플레이), 독립적인 마우스 트리거(정지 후 클릭, 스크롤 후 멈춤), 키보드 트리거(기본값은 영문자 입력 후 Return 또는 모든 Return)의 세 그룹으로 나뉩니다. MyClip이 열려 있는 동안 자동 캡처하며, 앱을 종료하면 멈춥니다. 특정 앱을 제외할 수 있고 전체 디스플레이 캡처에도 제외 규칙을 적용합니다.
- **라이브러리를 로컬에 보관하세요.** 캡처와 노트는 Mac에 저장됩니다. 원본 캡처는 기본적으로 30일 후 만료되지만 저장한 노트는 남습니다. 보관 기간은 설정에서 바꿀 수 있습니다.
- **AI를 사용할 시점을 결정하세요.** 정리는 선택한 에이전트의 모델 서비스를 사용하며, 캡처와 노트를 클라우드에서 처리할 수 있습니다. 자동 정리를 끄면 처리하기로 선택할 때까지 새 캡처를 로컬에 보관합니다.
