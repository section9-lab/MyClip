# 性能与能耗

## 2026-10-30：后台刷新与 Backstage

现场 `/Applications/MyClip.app` 版本 0.6.25：主进程连续 CPU 读数约 48%–50%，OCR 无积压，Agent 子进程约 0.6%。进程采样指向 Backstage 的 SwiftUI 布局及批次收尾的 `memoryLint`。这只是当时负载的诊断，不是待机基线，也不是瓦特或续航测量。

### 修复

- **Backstage**：移除包含两份计时标题的 `ViewThatFits`，标题与控制按钮固定分行，历史仍为 58pt 行高加分隔线、最多显示 50 条。历史时间改成静态日期时间，去掉持续呼吸动画。秒级状态被隔离在小型子视图，页面不可见、应用不活跃、隐藏或窗口最小化时暂停计时。
- **状态发布**：权限、截图状态、资料库、看板、统计、Token 数据只在内容变化时发布。重复流式状态只更新最后活跃时间，不触发整页重绘；不同的工具/状态仍立即显示。
- **按域更新**：SQLite update hook 维护按表递增版本；独立看板/MCP 连接通过 `PRAGMA data_version` 保守失效全部域。截图/资料库、看板、统计和 Token 分开加载。工具执行日志不会让无关看板重新加载。
- **合并刷新**：多个并发刷新共享一项任务，过程中到来的刷新请求继续排队核对，不能丢失。版本在读取开始时记录，避免把中途发生、尚未读到的写入当成已经处理。
- **Memory**：目录树事件通知后台更新，显式读取仍立即检查元信息。按文件修改时间、创建时间、大小和 inode 缓存正文、解析结果、哈希；原子替换和改名不会被忽略。缓存最多 512 个文件，每 60 秒重新核对时强制清空，兜底处理刻意保留大小和时间戳的原位修改。未变化的记忆不重复写回 `memory_files`。
- **图片容量**：缓存目录统计，应用写入/恢复 OCR 文本/清理图片立即失效，外部目录事件也会失效，最多 60 秒重新核对。
- **校验**：按页面内容与版本复用标识符、敏感信息、长行和来源提取结果；实体名称正则只编译一次，并缓存页面对名称的匹配。页面变化失效对应结果，别名/名称变化使用新的匹配键。图谱关系、来源存在性、过期时间仍以当前资料库计算，不为了省电跳过安全检查。
- **后台预算**：低电量模式延后自动做梦，后台 OCR 每张间隔 500ms；温度严重或临界时延后后台 OCR 和自动做梦。用户手动整理、搜索、截图规则、权限保护、失败重试和图片保留期不改变。睡眠/会话退出时不进行周期性后台派发；采集计时器锁屏/睡眠时停止触发，恢复后继续。
- **采集**：保留原 150ms 输入触发检查的时间语义，增加 50ms timer tolerance；权限检查不再每 150ms 重复调用，而是约每 3 秒核对。实际截图前的系统捕获权限仍由 macOS 强制执行。

### 保留的兜底

3 秒循环现在是轻量队列/权限/恢复检查，不是每次全量读取。不能粗暴改成一分钟，否则会延迟故障恢复或排队任务。后台至多约一分钟重新核对文件和数据，目录通知通常更快；显式打开、搜索、编辑仍立即核对。OCR 无工作时结束当前处理任务，有新截图或后台检查时重新按需启动。

缓存只在内存，不引入数据库迁移或第二份事实来源。SQLite 回滚可能造成一次额外失效，但不能造成遗漏更新。统计与查找结果的缓存不用于替代事实、来源或任务状态校验。

```sh
bash Scripts/test.sh performance

```

性能检查直接编译真实 Core、模型与 Backstage，不依赖 XCTest 或完整 Xcode；需要 macOS 图形会话。采集使用测试替身，不向真实资料库写入或连接付费 Agent。执行详情 sheet 不在被测范围。

### 短时合成 CPU 结果

夹具：86 篇约 80 行的主题记忆，50 条执行记录（其中一条运行中）。Backstage 使用真实 AppKit 应用生命周期与窗口，确认应用激活且窗口显示，显示、隐藏各测 3 秒。计时依据绑定到对应的 NSWindow，而不是依赖 NSHostingView 默认的 scenePhase。读取的是该测试进程 user+system CPU 时间，不是系统能耗影响评分。

| 项目 | 实测 |
|---|---:|
| 20 次无变化刷新 | 0 次状态发布、0 次 Markdown 文件读取、0 次数据库/文件写入；约 0.0018 CPU 秒 |
| 校验冷缓存 / 热缓存 | 0.9178 / 0.0804 CPU 秒，结果完全相同 |
| 修复后 Backstage 显示 / 隐藏 | 约 5.92% / 0.11% CPU |
| 相同 Core、模型、夹具，仅换回旧 Backstage 显示 / 隐藏 | 约 36.65% / 37.47% CPU |

这里的旧 UI 对照仅替换 `490217a` 的 Backstage 源文件，不是旧版本整应用对照。可以复现：

```sh
git show 490217a:MyClip/Features/Agent/BackstageView.swift > /tmp/MyClipBaselineBackstage.swift
MYCLIP_PERFORMANCE_BACKSTAGE_SOURCE=/tmp/MyClipBaselineBackstage.swift bash Scripts/test.sh performance
```

这些结果表明：持续动画/布局导致的 CPU 浪费已在该夹具中消除，热校验能复用大部分工作。短时测量有抖动，不能据此承诺整机耗电下降相同比例，或把修复前现场的 50% 与不同负载的合成测试直接比较。

### 仍需在发行环境验收

完整 Xcode 应用构建、已有整应用 Backstage 滚动回归及实际电池续航，需要具备 Xcode 的机器与较长时间的对照。应在同一机器、亮度、电源、资料库和输入脚本下，对窗口隐藏、Backstage 静止、正常采集与批次收尾分别测量 CPU 时间、磁盘 I/O、唤醒和能耗。修改源码不等于更新 `/Applications/MyClip.app`；安装新构建前，旧应用仍执行旧代码。
