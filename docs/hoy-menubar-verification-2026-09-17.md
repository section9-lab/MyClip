# MyClip 菜单栏细节验证 · 0.6.5

依据用户补充的三张 Hoy / MyClip 对照截图，本轮只调整菜单栏头像、展开方式和悬停提示。上一轮资料库及主浮层改动保持原样。

## 最终规格

| 项目 | 修改前 | 修改后 |
| --- | --- | --- |
| 头像 | 当前 33 pt 菜单栏内只画 22 pt | 26 pt 圆形，位于菜单栏垂直中央；更矮的菜单栏自动缩小 |
| 展开间隙 | 10 pt | 4 pt |
| 收起重叠 | 8 pt | 8 pt |
| 菜单栏占位 | 从 44 pt 突变为 68 pt | 固定 56 pt，头像在内部各移动 6 pt，180 ms 缓出 |
| 悬停外观 | 蓝色描边 | 轻微中性底色；保留原生键盘焦点 |
| 提示胶囊 | 30 pt 高、强制深色、统一白字 | 24 pt 高、系统适配浅深色、半径 12 pt、1 物理像素描边 |
| 文字与留白 | intrinsicContentSize 少算约 4 pt，短中文也被省略 | 使用 sizeToFit，左右各 10 pt 布局留白；名称与状态分层 |
| 提示位置 | 相对图标底部固定偏移 | 菜单栏底部下方 4 pt；横向保留屏幕边界 8 pt |
| 提示节奏 | 进入即显示，状态刷新时隐藏并重建 | 停留 400 ms 后显示，移开或点击立即取消；未变状态复用内容 |
| 状态内容 | 直接拼接后台详情 | 显示完整简短状态；详细错误与下一步仍在点击后的浮层中 |

数值是本轮 MyClip 原生组件的实测结果。用户截图用于比较比例与层次，未把截图像素直接当作所有显示器上的 pt。

## 验证

- 先复现：短中文提示可用宽度 97 pt，但 sizeToFit 需要 101 pt；初始检查有四项失败。
- 原生 AppKit 验证程序直接编译本次菜单栏与角色源码，使用隔离的状态模型：最终 **51 项断言通过**。覆盖两个助手的七种状态、完整文字、左右留白、悬停延迟与取消、快速切换、内容复用、重叠命中、头像上下边缘点击、14 个动画采样、正确浮层与重复点击关闭。
- 同步改变 NSStatusItem 宽度的尝试出现中间帧漂移，已改成固定占位；最终动画采样中窗口位置、占位和头像组中心保持不变。
- 使用 CUA 检查真实 AppKit 组件的浅色、深色外观；补查了细描边。组件窗口用于验证真实控件的视觉，不是重新画的 HTML 模型。
- 调试应用以 `--preview` 使用临时资料库，实测 `⌘⇧1` 打开 Codex、`⌘⇧2` 切换 Claude、`Esc` 返回资料库。
- `swift test`：151 项，145 项通过、6 项按原配置跳过，无失败。跳过的真实 Agent / adapter 集成检查未被计为通过。
- Debug 构建成功；发布构建与安装结果见下方安装记录。
- 更矮菜单栏、第二显示器、全屏 Space、VoiceOver 和系统 Reduce Motion 开关未作完整设备实测。减少动画路径与既有逻辑保留。

验证材料位于 `build/hoy-menubar-polish/`，包括 `harness.swift`、`combined.swift`、失败与通过日志、构建日志和安装记录。验证副本仅放宽了源码的 private 可见性，以读取几何与生命周期；没有改变被测分支。真实资料库不参与组件验证。
