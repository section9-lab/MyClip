# Hoy 交互研究与 MyClip 改进建议

研究日期：2026-09-17。已安装版本：Hoy 0.9.5（6），MyClip 0.6.2。代码依据为本次工作区，未假定已安装应用与工作区逐行一致。本轮只新增研究文档，没有修改产品代码。

## 结论

MyClip 最值得学习的是 Hoy 的**就地操作、稳定的操作位置、明确的状态反馈，以及操作中途不丢上下文**。MyClip 已有菜单栏双角色、原生浮层、真实队列和 Markdown 阅读基础；首要工作是让这些能力在界面中形成清晰的顺序。

建议把菜单栏浮层整理成：**当前助手 → 实际状态及下一步 → 最近成果 → 资料库与更多操作**。角色继续承担亲切感，状态和成果承担主要信息。

从设计模板感看，两者都具有明确的 macOS 原生基础。MyClip 当前的问题主要是信息权重：136 pt 的可交互角色、笼统问候、较弱的成果摘要和分散的状态入口。继续增加卡片、阴影、渐变或角色动作，收益有限。系统字体、原生控件和克制的系统蓝适合本项目，应保留。

## Hoy 的细节，如何转化为 MyClip 的设计

### 1. 先确定对象，再提供动作

用户截图里的头像与下方浮层靠近；输入提示带收件人的名字。视觉位置和文字一起说明“这次操作面向谁”。官方也把菜单栏作为文字、语音、视频和文件的主要入口。[官网](https://gethoy.app/)

MyClip 已为 Codex、Claude 分别提供按钮，并按所选图标定位箭头，方向正确。应继续保证点击同一角色关闭、点击另一角色切换，切换时不短暂展示上一个角色的成果。状态中要区分“正在查看的助手”和“后续截图使用的默认助手”。

不要把 Hoy 的“长按录音”直接套到 MyClip：两者的核心工作不同。现阶段一次点击看懂状态和最近成果，更值得优先完成。

### 2. 浮层内部有明确的大小关系

用户截图中，内容气泡随短句收窄，输入区较宽，二者左边缘对齐。输入文字和工具条分成两行；四个辅助工具使用较低对比，右侧蓝色主按钮成为操作终点。圆角和阴影帮助区分悬浮层级，留白帮助区分内容与操作。

这里应借鉴的是**内容、辅助动作、主动作的相对权重**。截图经过缩放，不能把截图像素直接作为 macOS 的 pt。Hoy 设置还提供 Circle/Squircle 与 Glass/Space；MyClip 没有必要为了外观相似增加这些偏好项。

### 3. 引导使用真实界面的操作位置

实测引导从 1 of 6 推进到完成，文字和视频进入内容区，底部按钮保持在同一位置。完成后，输入区可编辑且获得焦点；内容为空时 Drop 禁用，输入两行文字后启用；Shift+Return 插入换行。

MyClip 可以用三个真实里程碑组织首次体验：选择并理解采集范围、保存第一张截图、打开第一篇带来源的记忆。每一步都要用真实成功事件推进。系统权限和助手连接在需要时解释，不把 ACP、MCP 或批处理规则作为首次阅读的主内容。连接失败时应停留在可恢复的位置。

不建议照搬六步聊天教程。MyClip 更适合短小的行内引导；用户完成当前动作后，提示自然退出。

### 4. 搜索是临时状态，保留正在做的事

实测：⌘F 将焦点放到搜索框；无匹配时显示 No results；第一次 Esc 清空搜索词，第二次退出搜索模式。右侧频道和未发送草稿在这个过程中保留。本次两行测试草稿最终已手动清空。

MyClip 的搜索框声称覆盖任务、记忆和截图，但目前各页面分别显示自己的结果。第一阶段可保留这种结构，明确当前结果范围，补齐无结果提示、清除入口和键盘语义。之后再评估是否需要跨模块聚合结果，不必先建设一个新的搜索中心。

代码中搜索内容一变就清空选中文档及目录，因此退出搜索时恢复阅读位置需要专门设计。应保存进入搜索前的文档、目录和滚动位置。本轮没有可靠确认 MyClip 的 ⌘F/Esc 行为，不将其列为已复现的快捷键故障。

### 5. 反馈出现在动作附近，给用户反悔机会

Hoy 内置演示中，多附件先显示缩略图、逐项移除入口及 Drop 按钮；不能仅根据“拖到头像”的宣传语假定所有拖拽都会立即发送。实测的新建频道失败提示说明了原因，并给出释放空间或由他人托管的替代方向。

MyClip 的对应设计是：失败旁边提供针对当前批次的恢复操作，明确已经保存的截图和记忆是否保留。建议不要把所有故障都变成只有“好”的通用警告。Hoy 这次容量提示本身也只有 OK，没有直接的处理入口，这一点还可以做得更好。

### 6. “顺手”来自系统边界处理

Hoy 的更新日志明确涉及中文等输入法半输入文本、点击候选窗/表情面板时浮层不应关闭、浮层靠屏幕右边不应裁切，以及切换 Space 后 Esc 仍能取消录屏。它们是官方记录，本轮没有独立复测。[更新日志](https://gethoy.app/changelog)

MyClip 需要把同类场景纳入验收，尤其是原生浮层、Markdown 编辑器、系统授权窗和多显示器之间的切换。外观相似不能代替这些边界行为。

## MyClip 优先处理的问题

### 第一批：两处已经明确的语义问题

**搜索无结果被当作首次使用。**

复现：时间线已有截图 → 输入 `zz-hoy-review-no-match-20260917` → 结果为空。实测此时显示“记录当前的应用窗口”、采集触发说明及蓝色“暂停采集”，同时仍显示资料库总图片数量。用户本来是在找东西，界面却引导他停止采集。

改法：区分资料库为空、当前筛选为空、搜索无结果。搜索无结果显示“没有找到相关截图”，主操作为“清除搜索”；筛选为空显示“该应用暂无截图”，提供清除筛选。全库图片数量若保留，明确标注“资料库共…”，不要让它看起来像结果数。位置：[CaptureLibraryView](/Users/jackwang/Documents/GitHub/MyClip/MyClip/Features/Library/MyClipViews.swift:535)。

**采集范围文案与可选功能不一致。**

代码已支持焦点窗口和所在显示器两种范围；权限说明仍写“只记录你正在使用的窗口”，空状态写“整个桌面不会被采集”。默认键盘触发是字母后回车，而部分说明简写为任何回车。这些文字应从当前设置生成，不能继续作绝对承诺。位置：[采集设置](/Users/jackwang/Documents/GitHub/MyClip/MyClip/Core/CaptureSettings.swift:23)、[权限说明](/Users/jackwang/Documents/GitHub/MyClip/MyClip/Features/Library/MyClipViews.swift:953)。

验收：焦点窗口/显示器、不同键盘触发设置下，权限说明、空状态、状态提示含义一致；搜索和清除筛选不改变采集开关。

### 第二批：把浮层改成可靠的工作入口

**状态没有完整进入浮层。** 实测主窗口显示“整理已暂停 · 204 张等待”，Codex 浮层却主要呈现“等你叫醒我 / 尚未连接”。这里的 204 是主窗口全局队列数，不等于已确认的 Codex 队列数。模型已经提供按助手计算队列状态的方法，可直接复用。位置：[organizationStatus](/Users/jackwang/Documents/GitHub/MyClip/MyClip/Features/Library/MyClipModel.swift:408)。

**角色的视觉和键盘权重过高。** 当前角色尺寸为 136 pt。通过 ⌘⇧1 打开浮层时，实测焦点首先落到“打个招呼”角色按钮，出现大面积焦点环；连接按钮反而是弱样式。建议角色约 56–72 pt，置于状态旁；键盘首焦点给最有用的当前操作。若保留打招呼互动，保留可访问性，但放在主要操作之后，不能只隐藏焦点环来掩盖顺序问题。

**最近成果不足以帮助判断。** 实测最近记忆只显示日期标题和“最近整理”。建议显示标题、相对更新时间，以及来自正文的一小段摘要；没有可靠摘要就省略。不要在此额外调用模型生成摘要。来源数量存在且有效时再显示；点击进入对应文档并定位，返回时保留阅读位置。

以上可集中改在 [AgentMenuPanel](/Users/jackwang/Documents/GitHub/MyClip/MyClip/Features/Library/MyClipViews.swift:989)，继续使用现有 [ClipAgentState](/Users/jackwang/Documents/GitHub/MyClip/MyClip/Core/ClipAgentState.swift:3)，无需先重写后台队列。

### 第三批：统一可预期的操作路径

时间线实测同时存在边栏底部、页面内、窗口工具栏三个采集开关。应明确一个全局位置和一个首次引导入口；有内容后减少页面内的重复控制。保留系统菜单中的退出命令，是否继续在边栏常驻“退出 MyClip”应结合用户需求决定，本轮不直接删。

继续保留 Memory 的独立文件树、真实 Markdown、紧凑工具栏、折叠来源。这些符合知识阅读需求，不适合改成 Hoy 的聊天气泡或频道卡片网格。

## 建议浮层状态表

表中数字和文案示例用于说明设计，不是当前资料库数据。状态可以共存，应组合展示；优先级只决定最醒目的提示和主操作。

| 条件 | 用户应读到什么 | 主操作 | 同时保留 |
| --- | --- | --- | --- |
| 有待处理授权 | “需要你确认”，展示具体操作、对象、范围 | 使用真实授权选项 | 取消、最近成果；不自动允许 |
| 本批失败 | “本批未完成”，实际原因及已保存内容的情况 | 重试本批；连接故障则连接与修复 | 详情、最近成果 |
| 未连接 | “Codex 尚未连接”，有待整理内容时显示数量 | 连接 Codex | 已保存记忆可读；不假定已自动恢复队列 |
| 连接/安装中 | 当前步骤 | 必要时取消 | 不提供重复启动；不虚构百分比 |
| 正在整理 | “正在整理本批 6 张”，另有多少等待 | 不强行放一个蓝色按钮 | 次要操作“取消本批”；进度只用真实可用数据 |
| 整理被暂停 | “整理已暂停 · 6 张等待”，注明采集是否仍继续 | 恢复整理 | 查看记忆、更多 |
| 自动整理关闭 | “已关闭自动整理”，现有待处理数量 | 有可处理内容时“立即整理” | 自动整理设置；不把开关关闭误报为故障 |
| 排队等待 | “6 张等待 · 约 1 分钟后整理” | 立即整理（满足后台条件时） | 查看记忆；刷新不改变原排队起点 |
| 完成 | “已更新 2 篇记忆”，展示实际成果 | 查看最新记忆 | 简短完成表情后回到安静状态 |
| 就绪且无待处理 | 简短就绪状态；采集是否开启 | 有成果时查看记忆；无成果时首次引导 | 不持续呼吸、不伪造活跃感 |

授权及失败信息不能被完成表情覆盖；这项优先级已有代码基础。采集、整理、助手连接是三个独立概念，不能用一个绿点同时代表全部。切换默认助手只影响后续截图，既有队列归属保持不变，文案应说明这一点。

## 视觉与交互规格建议

以下数值都是 MyClip 的建议起点，应通过原生界面验证：

| 项目 | 建议 |
| --- | --- |
| 浮层宽度 | 先保留约 330–360 pt，内边距约 20 pt；长授权说明允许纵向增长或进入详情 |
| 信息顺序 | 助手与状态 → 最近成果 → 当前操作 → 资料库/更多；不常驻调试字段 |
| 字体 | 系统字体；主要内容约 13–15 pt，辅助文字约 11–12 pt；避免将关键错误缩成小字 |
| 角色 | 56–72 pt 起步，仍明显大于菜单栏图标；动作用于状态及短暂回应 |
| 颜色 | 单个当前主操作使用系统强调色；警告和错误配图标与文字，不只靠颜色 |
| 文案 | 先说事实，再加温度：“整理已暂停”比单独“我在呢”更有用；技术原因可展开 |
| 对齐 | 状态、成果、按钮形成共同左边缘；相邻文字间距小，功能组之间间距大 |
| 菜单栏动作 | 已有 180 ms 展开、220 ms 离开缓冲，可先保留；这是 MyClip 代码参数，并非 Hoy 的测量值 |
| 提示气泡 | 若实测出现鼠标路过就闪出的干扰，再增加约 350–500 ms 悬停延迟；不要先盲改 |
| 位置信任 | 同一头像重复点击切换显隐；跨头像切换保持锚点；菜单栏宽度变化、屏幕边缘不漂移 |
| 键盘 | 主要动作优先获得焦点；Esc 先处理最内层；关闭只读浮层不影响后台工作 |
| 可访问性 | 角色、按钮、状态有可读名称；键盘焦点可见；Reduce Motion 保留状态文字及静态提示 |

已有 [菜单栏控制器](/Users/jackwang/Documents/GitHub/MyClip/MyClip/Features/Library/MyClipMenuBar.swift:6) 负责图标独立命中、展开收起和箭头定位，[角色绘制](/Users/jackwang/Documents/GitHub/MyClip/MyClip/Features/Library/AgentCharacterView.swift:5) 已处理 Reduce Motion、完成表情和注意状态。应优先复用并验证。

## 验收清单

| 场景 | 合格表现 |
| --- | --- |
| 搜索无结果、筛选无结果、资料库为空 | 三种文案与主操作不同，不误切采集状态 |
| 改变采集范围或键盘触发 | 所有可见说明与实际配置一致 |
| 未连接且有积压 | 用户看得到连接问题和该助手待处理数量，也能打开旧记忆 |
| 采集继续、整理暂停 | 两种状态都明确；恢复整理不偷偷修改采集开关 |
| 双角色快速切换 | 内容与选中角色一致，旧成果不闪现，箭头不偏移 |
| 鼠标跨过两个重叠图标 | 前景图标拥有可见重叠区；展开中不误触另一个角色 |
| 打开浮层再按 Tab/Shift+Tab | 顺序符合任务；核心动作可到达；无装饰元素截断路径 |
| 空输入、空格、中文输入法组合态 | 不误提交、不丢半输入文字；候选窗操作不使编辑浮层消失 |
| 搜索中退出 | 查询、选择和阅读位置按既定规则恢复；编辑草稿不丢 |
| 整理进行中关闭浮层 | 后台任务继续；再次打开读到真实状态 |
| 授权、失败、完成同时临近 | 授权/失败优先且持续可见；成功表情不掩盖它们 |
| 取消或失败后重试 | 已保存截图和记忆仍在；明确本次重试范围；不会重复创建批次 |
| 深色外观、Reduce Motion | 文字和焦点清晰；减少动作不等于失去状态反馈 |
| 菜单栏最右侧、第二显示器、切换 Space | 浮层可见且不裁切；关闭和焦点行为一致 |
| 长中文标题、无摘要、无最近记忆 | 不挤压动作；必要处换行；诚实显示空态 |
| 原图尚在加载、原图过期、读取失败 | 三者有区别；当前代码初始 image 为 nil 就显示“图片已过期”，需专项验证是否造成闪烁或误报 |

建议执行顺序：先修正搜索空态与动态文案；再集中调整浮层的状态、成果和焦点顺序；最后补首次成功引导及系统边界验收。第一轮不需要增加录音、聊天、主题切换或新的后端抽象。
