# 桌面账号的 ACP 记忆生成

截至 2026-10-25，千问办公与 WorkBuddy 已通过本机真实账号的完整记忆生成和增量编辑验证。MyClip 自己维护账号与协议适配，不要求安装、运行或调用 Magpie，也不安装其插件。参考代码的来源、修改和 MIT 许可随 `MyClip/Core/Resources/SubscriptionAgent/LICENSES.txt` 分发。

## 实现

MyClip → 自有 ACP 连接组件 → 共享 OpenCode 工具执行器 → 自有图文/工具协议适配 → 千问办公或 WorkBuddy 产品账号 → Markdown 写入 → 来源校验和入库。

执行器和账号来源分别展示。使用产品账号的模型与额度，不等于接管桌面窗口里现有的对话或全部桌面专属工具。MCP 召回仍是独立功能，验证时关闭了测试库的 MCP 召回。

- `AgentRuntime` 的千问办公与 WorkBuddy 默认连接不以桌面应用、开发工具或命令行的安装为前提。首次连接由 `ManagedAgentRuntime` 使用系统网络 API 下载官方 Node 和 OpenCode 原生执行器，先验证发布清单中的 SHA-256/SHA-512，再解包并检测版本，最后写入就绪凭据。失败可重试；后续连接复用已准备的组件。
- 组件保存在当前资料库的版本化 Runtime 目录，支持 Apple Silicon 与 Intel（使用 baseline 构建）。兼容版本、平台下载地址和摘要由随应用发布的 `runtime-distribution.json` 管理；这是发布兼容性配置，不是用户路径、账号或模型列表。不会在用户电脑上运行 npm 安装或修改全局工具。Node 与 OpenCode 的许可证一并保留。
- `SubscriptionAgentCommand` 只将本地连接组件标记为允许访问对应账号的进程。普通 Agent 或用户自定义 ACP 命令不获得账号钥匙串权限。
- `providers.mjs` 直接完成同一产品账号授权、模型目录和额度读取；`qwenwork-protocol.mjs` 处理千问办公流式协议、图片和工具转换。没有静态型号清单或其他提供方自动降级。
- `agent.mjs` 管理 ACP 转发、执行器生命周期和仅监听 `127.0.0.1` 随机端口的进程内模型接口。该接口使用随机短期密钥，账号令牌不进入执行器配置、环境变量、参数或磁盘文件。退出时停止自己创建的执行器进程组。
- 执行器配置、账号和运行目录按资料库及产品隔离；不读取 Magpie 的配置或账号，也不读取、解密桌面端凭据。
- 账号连接不继承宿主进程的其他提供商密钥、Node 注入选项或 OpenCode 配置；只保留系统路径、语言及网络代理/证书设置。每个用户授权自己的账号，模型与额度均由该账号实时返回。
- 系统钥匙串复用原有 `KeychainDataStore` 实现。后台读取不弹系统认证窗口；明确点击重新授权时才允许系统交互。解锁失败或无访问权限显示错误，不把后台等待当作连接成功。

## 应用内操作

在 Backstage 连接千问办公或 WorkBuddy，按提示在浏览器使用桌面端的同一账号授权。连接后显示账号、套餐及服务实际返回的额度，模型由授权账号实时提供。总额、已用值缺失时可单独显示剩余额度，不能补零或推算百分比。

支持取消授权、重新授权、刷新模型与额度。选择只在 ACP 确认后按 Agent 保存。自定义 ACP 可执行路径仍按用户指定的原有方式运行，不被替换成账号桥接。

WorkBuddy 5.6 以后的桌面凭据已加密，因此本实现通过同一账号的独立浏览器授权复用产品订阅，不承诺零点击复用桌面会话。企业账号必须带原组织身份，不自动改用个人额度。

WorkBuddy 的服务端点与兼容协议版本集中在 `account-protocols.json`。安装了桌面应用时可读取其公开版本元数据，未安装时使用发布审核的兼容版本；两者都不读取桌面凭据。千问办公的公开协议参数同样通过资源文件管理。

认证过期、模型移除、图片/工具不支持、额度或渠道拒绝均保留失败。不会通过身份改写绕过渠道拒绝；即便执行器在上游拒绝后返回 `end_turn`，连接组件也会将未恢复的上游错误作为 ACP 失败返回。

## 实际验证

用户完成两个产品的同账号浏览器授权后，使用真实 `MyClipModel.processNext`，分别运行首次生成与已有记忆增量编辑。使用独立偏好域、测试图片和隔离资料库，不启动正式采集、云同步或自动工作队列。

| 产品 | 账号返回的模型数 | 首次工具调用 | 增量工具调用 | 图像事实、文件、来源和入库 |
| --- | ---: | ---: | ---: | --- |
| 千问办公 | 3 | 10 | 17 | 两次通过 |
| WorkBuddy | 19 | 5 | 8 | 两次通过 |

每次图片都有新的随机参考编号，未写入 OCR 或提示词。两者都正确提取并写入该编号和周三 16:20 的事实，实际新增或修改 Daily、项目 Wiki、Memory 导航等 Markdown，关联对应测试截图后入库。工具事件包含读取、写入、编辑和命令执行。

WorkBuddy 授权账号 ID 与桌面公开账号信息匹配；套餐额度接口读到 0.49 / 500。千问办公由用户确认同一桌面账号，服务返回“个人免费版”和剩余额度，不返回总额及已用值。额度是账号接口的瞬时读数，不能用同期间余额差断言单次测试费用。

本地证据在 Git 忽略目录 `build/diagnostics/subscription-agents-20261025/`：首次与增量验收 JSON、测试库及 Markdown、额度核对和各项检查日志。短期成功不代表所有模型、组织或未来产品版本都已验证。

## 自动检查

`bash Scripts/test.sh scripts` 包含独立协议检查：图像和工具转换、动态目录、个人及企业额度、剩余额度未知项、刷新串行化、渠道拒绝不重试，以及执行器正常结束但上游失败时的 ACP 失败传播。

`AgentActivationTests` 覆盖未安装桌面应用的首次连接和授权域名策略；`AgentModelTests` 以内存凭据和假进程验证普通 Agent 无权访问账号、指定连接组件才能轮换凭据、额度元数据和现有六种 Agent 模型选择。`Tests/SubscriptionAgent/run.sh` 检查干净用户环境、跨用户隔离、中文与空格路径、下载校验、损坏恢复、离线重试和进程环境隔离。真实账号验证与模拟检查分别记录。
