## できること

- **作業を振り返る。** キャプチャを時系列で確認し、ノートの根拠となる資料に戻れます。各キャプチャにはローカルの OCR テキスト文書があり、閲覧、コピー、ファイルとして開く操作ができます。
- **個人のナレッジライブラリを作る。** プロジェクト、テーマ、日々の作業を横断してノートを検索、編集、リンクできます。ノートは Markdown ファイルなので、ほかのエディタでも開けます。
- **次の作業を把握する。** 提案されたタスクを確認し、必要なものを承認して、ボードで進捗を追えます。**Kanban** と **Reports** を切り替えると、プロジェクトと進捗別に整理された日報、週報、月報を閲覧できます。
- **AI ツールに文脈を渡す。** Codex、Claude Code、Claude Desktop、Cursor、OpenCode から、保存したメモリを検索できます。

## はじめに

**macOS 13 以降**と **Codex または Claude のアカウント**が必要です。エージェントのコネクタをインストールするには **Node.js 22 以降**も必要です。ローカルでのビルド方法は末尾をご覧ください。

1. MyClip を開き、サイドバーの **Backstage** に移動します。コネクタをインストールしてログインし、**Connect** で利用可能か確認します。その後、**Enable** で整理に使用するエージェントを有効にします。接続するだけではタスクは始まりません。複数のエージェントに接続できますが、同時に有効にできるのは一つです。
2. **画面収録**と**アクセシビリティ**の権限を許可します。MyClip が開いている間は自動的にキャプチャされ、権限を許可した直後も開始します。
3. 普段どおり作業してください。既定では、ポインタを 1 秒静止させた後のクリック、縦スクロールが止まってから 2 秒後、または英字キーの後の Return でアクティブウインドウをキャプチャします。自動整理によって、新しいキャプチャが Memory にまとめられます。
4. ノートは **Memory**、キャプチャは **Timeline**、タスクの候補は **Kanban** で確認できます。

AI ツールでメモリを使うには、設定で **MyClip MCP** を有効にし、クライアントを選んで設定を適用します。その後、クライアントを再起動するか、新しいセッションを開始してください。

**Claude Code（CLI）**は、ACP を通じてバックグラウンドでキャプチャを整理します。**Claude Desktop** には別の項目があり、アプリを開いたり、Chat やローカルの Code セッション向けに MCP メモリアクセスを設定したりできます。バックグラウンド整理用には有効化できません。デスクトップ版の設定は `~/Library/Application Support/Claude/claude_desktop_config.json` に保存され、既存のサーバーを保持し、CLI の設定は変更しません。設定後は Claude Desktop を完全に終了してから開き直してください。

## キャプチャのテキスト文書

MyClip は Apple Vision を使い、中国語と英語の文字を端末内で認識します。AI による整理とは独立して動作します。キャプチャの詳細で **OCR 文档** を選ぶとテキストを読んだりコピーしたりできます。**打开文档** では、元画像の隣に保存された UTF-8 の `.txt` ファイルを開けます。同じ内容のキャプチャは画像と文書を共有します。読み取れる文字がない場合は空の文書になり、認識に失敗した場合は再試行できます。

既存のキャプチャは起動後にバックグラウンドで処理されます。OCR 文書と検索インデックスは、保存期間の設定に従って元画像と一緒に期限切れになります。保存済みの Memory ノートは残ります。対応 OS は macOS 13 以降で、macOS 27 も含みます。macOS 13 では 1 フレームの ScreenCaptureKit ストリームを使い、新しい OS と同じアプリ除外設定を適用します。

## キャプチャの整理

キャプチャは保存されるとすぐ、永続化された待機キューに入ります。自動整理は最も古い未処理キャプチャから 3 分待ち、同じエージェントに対して時系列順にバッチを組みます。上限は **画像 8 枚と OCR レコード 32 件**、OCR テキストは合計 **12,000 文字**です。Return と手動操作によるキャプチャは画像を使い、クリック、スクロール、旧ポインタトリガーによるキャプチャはローカル OCR を使います。未生成の OCR は送信前に作成します。空、失敗、単独で長すぎる OCR は元画像に切り替え、画像数の上限に数えます。上限を超える最初のレコードに達したら、そのレコードを飛ばさずにバッチを終了します。新しいキャプチャが追加されてもタイマーはリセットされません。一度に実行するのは 1 バッチで、開始時刻の間隔は最低 3 分です。

**Backstage** には待機数、カウントダウン、現在のバッチが表示されます。**Organize Now** で 1 バッチを早めに開始できます。失敗や中断が起きると、再試行または再開するまで自動処理は一時停止します。キャプチャと既存の Memory ファイルは保持されます。入力モードと OCR の内容はバッチ作成時に固定され、再試行や再起動でも変わりません。キャプチャ詳細の **按图片重新整理** は元画像を明示的に送信する操作で、OCR では保持できない図やレイアウトに適しています。別のエージェントを有効にすると、自動整理待ちのキャプチャが再割り当てされます。実行中のバッチは元のエージェントで完了します。既存のジョブと再試行も元のエージェントを維持し、再び有効になるまで待機します。

各バッチは独立した一時セッションを使います。Claude には `persistSession: false` を渡します。MyClip の Codex app-server プロキシは `ephemeral: true` を必須とし、確認を返さないバックエンドは拒否します。各実行の終了後、エージェントのプロセスを閉じます。以前に保存された会話を再開したり削除したりはしません。次のバッチには、固定の整理ルール、直前に成功したバッチの引き継ぎ情報のみ（最大 4 KiB）、タイムスタンプとソース ID 付きの今回の入力、アプリ・ウインドウ・トリガーのメタデータ、既存タスクの文脈を渡します。関連する Memory ファイルは必要に応じて読みます。引き継ぎ情報には保存済みファイルの変更とソース ID を記録し、会話履歴や Memory 本文は含めません。Memory の公開が成功した後にだけ置き換えます。失敗後の再試行は新しいセッションで開始し、現在のファイルを確認します。

有効なエージェントがなければ、キャプチャは待機キューに残ります。エージェントを無効にすると新しいタスクの割り当てが止まり、実行中のタスクは完了できます。MyClip は有効なエージェントを記憶し、起動時に再接続します。旧版の既定エージェント設定から自動的に有効化されることはありません。アップグレード後は明示的に有効化してください。

MyClip はすべての整理・タスク検出セッションを**フルアクセス**で開始します。Codex は `agent-full-access`、Claude Code は `bypassPermissions` を使用します。ファイルアクセス、編集、コマンド、ネットワークアクセス、MCP ツール呼び出しのたびに確認カードは出ません。残りのツール権限要求もアクティブなセッションでは自動処理されますが、キャンセル済みのタスクは遅れて届いた要求を拒否します。ツールの活動は実行記録から確認できます。

**Backstage** は、整理、タスク検出、再試行で報告されたトークン使用量を、エージェント別・バッチ別に集計します。各リクエストの終了時にローカルへ保存します。古いデータや未報告のデータは、ゼロではなく取得不可と表示します。コンテキストウインドウの占有量は消費量に含めません。実行中のバッチには、現在の段階、経過時間、最後の進捗更新からの時間が表示されます。Claude ACP は Claude Code の既存のログイン・ネットワーク設定を使うため、設定済みのローカルプロキシは起動しておく必要があります。

現在のセッションで新しい思考、返信テキスト、ツール動作、権限関連の動作が 5 分間なければ整理を停止します。進捗が続く場合でも、1 バッチの実行時間は合計 15 分までです。使用量だけの更新や別セッションの活動ではタイムアウトは延長されません。

Memory は、キャプチャの観測時刻（`observed_at`）とファイル更新時刻（`updated_at`）を分けて保持します。Now には根拠がキャプチャされた時刻を表示し、古い根拠が新しい Now ページを上書きすることはありません。観測時刻がなければ不明のままにします。整理処理はイベント履歴を Daily にまとめ、結論をプロジェクト・トピックのページに保存し、解決済みの項目を Inbox から移します。繰り返しの閲覧や偶発的な閲覧のたびに永続ノートを作る必要はありません。

新しく整理したページの `source_ids` には、本文で実際に引用したキャプチャの ID が入ります。バッチの参考キャプチャは `context_source_ids` に別途保存され、すべての記述の根拠にはなりません。MCP の検索結果には各段落で引用されたソース ID が含まれ、`memory_get` はページの背後にあるキャプチャを要約します（件数、期間、アプリ）。既存のノートは引き続き読め、再整理時にこのルールを適用します。アップグレードでノートを一括書き換えすることはありません。

アプリと MCP の検索は、同じ SQLite FTS5 のランキングを使います。キーワードは一部の語への一致でも検索対象になります。まず完全一致するタイトルと登録済みのエイリアスを優先し、次に各ノートで最も一致する段落とノート全体の BM25 を組み合わせ、最後にファイル更新時刻で並べます。段落単位で採点することで、長いノートが実際に質問に答えている段落を押しのけることを防ぎます。中国語や句読点にはリテラルな部分文字列一致も利用できます。空のクエリでは最近編集したノートを表示します。

MCP は読み取り専用の 2 つのツールを提供します。`memory_search` は `query`（質問やキーワード）と、任意で `since`、`until`、`app`、`limit`（既定 10）を受け取り、`path`、`title`、短い `snippet`（最大 300 文字の一致段落を最大 2 件）、`time`、段落が引用する `sourceIDs`、ソースの `apps` を含むランク付き結果を返します。`memory_get` はこれらの結果から `path` を受け取り、任意で特定セクションを読む `#heading`、行範囲を指定する `from`/`lines` を受け取ります。戻り値は Markdown の行、見出しごとにまとめたページのリンク、新しい順のバックリンク（各リンクを含む行とその日付付き）、ページ背後のキャプチャの要約です。未知の引数は無視されず拒否されます。

検索は Wikilink をたどります。最も強い一致と、質問に一致する行を持つリンクの両端が種となり、リンクグラフ上を 2 段階でたどります。各種から 1 ホップ、さらにエンティティページ（Daily ノート → 人物やトピックのページ → 別の Daily ノート）を経由する場合のみ 2 ホップ目まで広げます。各リンクは、その行が質問にどれだけ一致するかで重み付けされ、遷移先のページが持つリンク数で減衰するため、`Now.md` のようなハブページが結果を埋め尽くすことはありません。ルートファイルと `Wiki/Archives` は対象外です。こうして到達したページは直接の一致と合わせてランク付けされ、`via`（1 ホップまたは 2 ホップ、それぞれリンクを含むページ、見出し、行そのもの、日付）を伴います。リンクは関連性を示しますが、事実関係の証明にはなりません。

`time` と `since`/`until` フィルタは、内容がいつ起きたかを表します。段落に付いたイベント注釈、なければ引用されたキャプチャ、それもなければファイル編集時刻の順です。`since` は境界を含み、`until` は含みません。どちらも ISO 8601 のタイムスタンプを受け付けます。`app` を指定すると、イベントを持つノートはそのアプリのキャプチャも引用するイベント段落を通じて一致し、イベントを持たないノートは範囲とアプリの両方を満たす引用済みキャプチャを 1 件必要とします。日付不明のイベントを、キャプチャ時刻や編集時刻で置き換えることはありません。範囲指定のない日付付きページは、最近の日をわずかに優先します。

イベント注釈は、対応する段落の直前に空行を挟まず HTML コメントとして保存します。Markdown のコピーやインデックスの再構築でも残ります。例：

```markdown
<!-- myclip-event {"start":"2026-09-10T00:00:00+08:00","end":"2026-09-11T00:00:00+08:00","precision":"day","evidence":"2026-09-10"} -->
2026-09-10 に顧客との会議が終了した。出典：キャプチャ `REPLACE_WITH_ACTUAL_SOURCE_UUID`。
```

実際の根拠と、引用した実在のキャプチャ ID を使ってください。精度は `day`（ローカル暦日）、`range`（終端を含まない明示的な期間）、`instant`（終端を省略、または開始と同じ時点）に対応します。タイムスタンプには UTC オフセットを明示する必要があります。検索は結果の `time` としてイベントの開始時刻を返します。これはノートの記述を記録したものであり、ソースを独立して検証した結果ではありません。不正な日付、矛盾する注釈、コード例内の注釈、段落の引用不足、段落に存在しない `evidence` 表現からは、イベント時刻のインデックスを作りません。相対日付には元メッセージの時刻とタイムゾーンが必要です。整理処理は元の表現を残し、換算方法を説明しなければなりません。キャプチャ時刻や編集時刻で欠けたイベント日付を補うことはありません。既存のノートは注釈がなくても検索でき、関連する根拠を整理する際に注釈を追加します。アップグレードで日付を創作・変更することはありません。

段落・イベント・リンクのインデックスは、派生した SQLite データです。編集時に更新し、ノート削除時に一緒に削除します。古いライブラリでも Markdown を変更せずに再構築できます。2 ホップを超える情報が必要な質問には、エージェントが `memory_get` でページを読み、そこに載っているリンクやバックリンクをたどります。

一時セッションは Codex や Claude で開き直せません。代わりに MyClip の実行詳細を確認してください。各記録には画像・テキストの入力数も表示されます。これらの設定が防ぐのは再開可能なローカルのエージェント会話であり、モデル提供者のサーバー側のデータ保持を決めるものではありません。

**Backstage** の整理記録をクリックすると、再試行を含む各リクエストのツール呼び出し、コマンド引数、結果、ファイルの場所と変更、エージェントの返信、入出力トークン、キャッシュの読み書き、報告された費用を確認できます。ツール記録は実行中に保存され、キャンセルや再起動後も残ります。費用は報告されたセッション累計額の差分で計算し、報告がない場合や基準額が不明な場合は不明のままです。古い記録のトークン合計は保持されますが、保存されていなかったツール詳細は復元できません。

## プライバシーと管理

- **キャプチャする範囲を選ぶ。** 設定は、範囲（既定はアクティブウインドウ、またはそのディスプレイ）、独立したマウストリガー（静止後のクリック、スクロール後の停止）、キーボードトリガー（既定は英字入力後の Return、または毎回の Return）の 3 グループに分かれています。MyClip を開いている間は自動でキャプチャし、終了すると止まります。特定のアプリを除外でき、ディスプレイ全体のキャプチャでも除外設定を守ります。
- **ライブラリをローカルに保存する。** キャプチャとノートは Mac に保存します。元のキャプチャは既定で 30 日後に期限切れになりますが、保存済みノートは残ります。保存期間は設定で変更できます。
- **AI を使うタイミングを決める。** 整理には選択したエージェントのモデルサービスを使い、キャプチャやノートがクラウドで処理されることがあります。自動整理を無効にすると、自分で処理を選ぶまで新しいキャプチャをローカルに保持できます。
