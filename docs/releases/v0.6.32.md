# MyClip 0.6.32

## Silent recovery for Memory metadata conflicts

- Fix an automatic-organization edge case where an Agent could regenerate a Markdown file’s internal ID while rewriting its front matter.
- Keep the established file path as the canonical identity when the generated ID belongs to no other Memory page, then import the edited content normally.
- Stop showing the unexplained global “knowledge updated” alert for revision conflicts; editable conflicts remain handled inside the Memory editor with draft-preserving choices.
- Strengthen organization instructions so Agents preserve MyClip-managed metadata such as ID, revision, update time, and source fields.

No Memory content is discarded. MyClip repairs only the accidental identity field and retains the page body, stable path, existing history, and search index.

## Updating

From **0.6.24 or later**, use **MyClip → Check for Updates…** to download, verify, install, and relaunch. Existing data, Memory history, capture settings, and Agent preferences are preserved.

## Validation

Validation covered the affected local Memory library on a copied data set, identity repair for known paths, body import and revision history, suppression of the generic conflict alert, Swift parsing, native model/view type-checking, and release metadata. The release workflow runs the complete core, adapter, packaging, benchmark, native-app, and signed-update checks on Apple Silicon and Intel before publication.
