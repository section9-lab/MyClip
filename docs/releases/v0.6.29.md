# MyClip 0.6.29

## Clear capture status and control

- Show whether MyClip is capturing, paused, preparing, or missing permissions in the sidebar and menu bar.
- Pause or resume capture without quitting from the sidebar, menu bar panel, or **MyClip** menu. The preference persists across launches.
- Keep existing Memory, Timeline, Kanban, Auto-organize, and Settings available when capture permissions are missing. The setup guide can now be deferred or cancelled instead of replacing the whole library.
- Replace permission-shaped switches with explicit authorization status and **Authorize** or **Open System Settings** actions.

## More native macOS behavior

- Open Settings in an independent resizable preference window and expose it through the standard **MyClip → Settings…** command.
- Add native File, Edit, View, Window, Services, and Help commands, including New To-do, Close, Redo, toggle sidebar, full screen, minimize, zoom, and Open Library in Finder.
- Show search only on pages that support it, with page-specific Memory, screenshot, and task labels.
- Add a visible Memory actions menu for edit, export, move, rename, and delete operations that were previously available only from the context menu.
- Improve control semantics, VoiceOver labels, permission status presentation, and selected-state feedback.

## Privacy

- Anonymous app-launch and daily-activity analytics are now off by default and require an explicit opt-in in Settings.
- Add the localized Screen Recording usage description and clarify what capture records and excludes.

## Updating

From **0.6.24 or later**, use **MyClip → Check for Updates…** to download, verify, install, and relaunch. Existing data and preferences are preserved. If macOS asks for Screen Recording or Accessibility again after the update, authorize `/Applications/MyClip.app` and restart MyClip.

## Validation

Local checks covered the core Swift build, anonymous-analytics opt-in behavior, capture pause and resume lifecycle, independent Settings routing, Agent activation, menu bar board behavior, Swift parsing and targeted view type-checking. The release workflow runs the complete core, adapter, packaging, benchmark, native-app, and signed-update checks on Apple Silicon and Intel before publication.
