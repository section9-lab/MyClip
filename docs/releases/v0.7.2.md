# MyClip 0.7.2

## One day, one folder of event pages

- Daily pages now live at `Daily/YYYY/MM/DD/YYYY-MM-DD-HH-topic.md`. The folder is the local date, the filename carries the event's start hour (two-digit 24-hour clock) and its topic, for example `Daily/2026/10/30/2026-10-30-19-系统设置浏览.md`.
- There is no `Daily/YYYY/MM/YYYY-MM-DD.md` and no date-named subfolder any more. A batch writes one file per event and appends to that file when the same event continues; it still cannot touch `Wiki/`, the root files, the board or the calendar.
- Weekly summaries keep their place at `Daily/YYYY/Weekly/YYYY-Www.md`; the weekly turn now recognises both the new filename shape and the older day pages.
- The hourly digest and Memory search read any page under `Daily/`, so links, recall and the board/calendar writes are unchanged.

## Existing vaults

Pages that already exist are left exactly where they are. Only pages written from this version on use the new shape, and the Agent maintains links to both. If you want to rewrite an existing vault into the new layout in one pass, do it with the app quit and keep a copy of `Memory/`, `Entries/` and `Library.sqlite` first — the hourly digest will then treat the rewritten pages as already processed.

## Updating

From **0.6.24 or later**, use **MyClip → Check for Updates…** to download, verify, install, and relaunch. Existing data, Memory history, capture settings, agent preferences, and calendar events are preserved.

## Validation

Core tests cover the new Daily path in the batch and digest prompts, weekly matching for the new filename shape, the digest watermark and scope, the write tools for the board and the calendar, idempotent replay, user edits surviving later synchronization, and the read-only Memory reader. The release workflow runs the complete core, adapter, packaging, benchmark, native-app, and signed-update checks on Apple Silicon and Intel before publication.
