# MyClip 0.7.1

## A display-only Memory reader

- The Memory page is now read-only. “Edit Markdown”, “Move or rename…” and “Delete entry” are gone; the page keeps reading, exporting Markdown, file information, and the two Finder shortcuts.
- File-level changes belong to the Agent. The hourly digest may move, merge, rename and delete pages, and it maintains every Wikilink that points at them while it does.
- `Profile.md` is maintained by the Agent from the material it reads: preferences, habits, working style and long-term goals, each line carrying its evidence. Nothing waits for a confirmation click; “待确认” in the text is a note about uncertain evidence, not a prompt to the user.
- The board and the calendar stay yours to manage. The digest writes them through tools only when the day's Daily pages actually involve a task or a dated commitment, and an event you edited or removed is never overwritten or brought back.

## Behaviour changes that arrived in 0.7.0

These were live in 0.7.0 but missing from its notes, so they are listed where upgraders will look:

- Memory writing is split in two. A batch only records the day into `Daily/`; the hourly digest is what turns those pages into `Wiki`, `Memory.md`, `Now.md` and `Profile.md`.
- Task recognition no longer runs on every batch. The board is updated by the digest, so a new card can appear up to an hour after the screenshot that mentions it.
- Backstage shows the two pipelines as separate cards, with the Daily pages waiting for the digest, when it last ran, and what it put on the board and the calendar today.

## Updating

From **0.6.24 or later**, use **MyClip → Check for Updates…** to download, verify, install, and relaunch. Existing data, Memory history, capture settings, agent preferences, and calendar events are preserved.

## Validation

Core tests cover the two pipelines, the digest watermark and scope, the write tools for the board and the calendar, idempotent replay, user edits surviving later synchronization, dismissals, and the read-only Memory reader. The release workflow runs the complete core, adapter, packaging, benchmark, native-app, and signed-update checks on Apple Silicon and Intel before publication.
