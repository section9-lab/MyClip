# MyClip 0.6.31

## Reliable Memory editing during background updates

- Fix the repeating “knowledge updated” alert that could appear when saving a Memory page after Auto-organize, cloud synchronization, or an external Markdown edit changed the same page.
- Refresh the latest revision when a conflict is detected instead of repeatedly retrying the stale revision held by the editor.
- Preserve the current Markdown draft and offer explicit choices: load the latest version, or save the draft deliberately as a new revision.
- Keep the conflict inside the editor instead of dismissing context with a generic application-wide alert.
- Clarify the fallback conflict message for proposal, move, and other revision-sensitive operations.

MyClip continues to reject silent overwrites. Saving a draft as a new revision preserves the previous version in local history.

## Updating

From **0.6.24 or later**, use **MyClip → Check for Updates…** to download, verify, install, and relaunch. Existing data, Memory history, capture settings, and Agent preferences are preserved.

## Validation

Local checks covered stale-editor conflict detection, retrieval of the newest revision, preservation of the in-progress draft, deliberate retry as a new revision, Memory core tests, Swift parsing, localized strings, and targeted native view type-checking. The release workflow runs the complete core, adapter, packaging, benchmark, native-app, and signed-update checks on Apple Silicon and Intel before publication.
