# MyClip 0.7.3

## A queue that never waits for a click

- Every failed batch goes back in line on its own, whatever stopped it: a timeout, a dropped connection, an overloaded provider, or a rejected result. Nothing pauses the queue and there is no retry button to press.
- The five-minute gap between batches is gone. When one batch finishes, the next one starts at once, and a retry waits five seconds instead of a backoff that grew to an hour.
- A backlog left by an earlier version is released on the next launch: queued batches whose retry time was still in the future start now, and batches that had failed are requeued with a fresh budget.
- New screenshots still collect for up to five minutes before a batch starts, so one batch has up to eight captures to read. The hourly digest and the nightly dream are unchanged.

## Updating

From **0.6.24 or later**, use **MyClip → Check for Updates…** to download, verify, install, and relaunch. Existing data, Memory history, capture settings, agent preferences, and calendar events are preserved.

## Validation

Core tests cover the queue's ready-time ordering without an inter-job wait, immediate requeue after a failure or an interruption, legacy pause recovery without an attempt cap, and the five-minute batching window for new captures. The native-app recovery suite checks that a failed batch is retried without a click and that an interrupted queue drains on startup. The release workflow runs the complete core, adapter, packaging, benchmark, native-app, and signed-update checks on Apple Silicon and Intel before publication.
