# 看板任务识别恢复

Memory 保存与任务登记分别记录结果。`finishMemoryEditing` 在标记整理作业完成的同一事务里写入 `task_ingestions`，然后任务阶段逐条校验和登记。每条任务、依据与状态事件保持原子性；一条无效候选不撤销其他候选。原始回复保留，失败候选与原因进入独立队列。

解析器提取完整的 JSON 对象，允许对象前后的说明文字，正确处理字符串里的括号和转义引号；多个任务对象、截断 JSON 或超过数量上限仍拒收。候选字段分别解码，来源必须属于冻结的截图或 Memory 目录。任务编号只能作为 `taskID`，不能作为来源。

后台使用当前选定的 Agent，在新会话中只读核对失败候选。每次核对冻结实际提供的 Memory 目录，也可通过 Memory 处理已过期截图。单次限时 5 分钟，最多自动重试 6 次，沿用已有退避策略，不暂停截图整理队列。重启后恢复中断的任务阶段；次数用完后在看板保留原因和重试入口。

旧版完成作业通过最新成功回复与已有依据指纹核对：空结果或已导入的依据直接完成，未登记候选先核对来源和任务身份，再导入。重复扫描和重复应用已完成记录不会重复新增任务或依据；来源的发生时间仍用于保护较新的人工状态。

`task_ingestions` 是兼容旧版的附加表，不改变现有表结构和版本号，允许补处理工具与尚未更新的本机应用共存。旧应用不会运行补处理队列，自动恢复需要新版本应用。

验证：`bash Tests/MyClipAppTests/run.sh TaskRecoveryTests`。使用临时资料库与 ACP 夹具进程，不需要账号或 XCTest，覆盖解析、逐条提交、来源拒绝、重启、退避、历史补偿、幂等和应用调度。
