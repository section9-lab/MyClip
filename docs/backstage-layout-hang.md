# Backstage 执行记录的布局反馈

## 现象与定位

长时间运行后，应用可能持续占用约一个 CPU 核心，窗口无法正常响应点击。现场线程采样集中在 `GraphHost.flushTransactions → LazySubviewPlacements → LazyStack.place`，同时出现执行记录和 Agent 图标的更新。

执行记录最多显示 50 条，每行高度固定，内层视口最多显示五行。原实现把 `LazyVStack` 放在内层 `ScrollView` 中，外面还有页面的 `ScrollView`。懒栈在滚动时使用估算高度；外层裁剪与内层滚动位置变化会再次影响子视图放置。这条路径在现场持续重新布局。

独立副本中可以稳定复现几何反馈：记录没有变化时，6 条记录的内容高度在 354 与 383/384 点之间变化；14 条记录出现 826 与 839 点的变化；更多记录还会发生滚动到顶部后的偏移。原生图标也存在额外失效：相同配置会再次请求重绘，每次布局都会移除并新建鼠标跟踪区域。

这些数字来自固定样式的原生复现窗口。长期卡死通过原进程采样确认；确定性的回归检查针对同一列表路径上的高度变化、偏移和重复失效，不依赖等待应用再次长期卡住。

## 修复

- 对最多 50 行的有界历史使用普通 `VStack`，直接计算完整高度，移除这一处懒栈的估算与放置路径。仍保留五行视口和内层独立滚动。
- 相同图标配置不请求重绘，不重复设置无障碍属性。真正改变状态、交互或外观时仍然更新。
- 静态图标不注册鼠标跟踪。动态图标复用带有 `.inVisibleRect` 的跟踪区域，由 AppKit 随可见区域调整；关闭动画或启用减少动态效果时移除跟踪。

不需要清理资料库、重建索引或删除历史记录。

## 回归验证

在具有完整 Xcode 和 macOS GUI 会话的环境中运行：

```sh
bash Scripts/test.sh app BackstageResponsivenessTests
```

检查使用临时资料库和生成的执行记录，不连接 Agent、采集屏幕或同步云端。覆盖 6、14、49、50 和超过显示上限的记录数；在外层页面不同位置滚动内层列表，校验高度、首末记录可达性、列表收缩和空状态。还会更新进度、完成任务、缩放窗口及隐藏后重新显示，并监测主线程响应。

对照 0.6.16 的代码运行相同检查，可以观察到几何和图标失效；修复后各记录数的高度恒定，滚动位置不再漂移。复现程序定位滚动视图时按父子关系查找，不能依赖原生视图数组的顺序。

2026-10-24 的独立验证结果：Debug 和 Release 的修复版各通过 21 项检查，旧版在两种构建中均出现 12 项失败；修复版最大主队列响应延迟分别为 0.453 秒和 0.368 秒。Agent 激活的 105 项检查及 Memory 目录的 22 项检查也通过。本机只有 Command Line Tools，完整应用编译通过临时 SwiftPM 工程完成，未进行 Xcode 打包或安装替换。

在独立 Release 窗口中，实际鼠标点击 Agent 图标、嵌套滚动、切换筛选、打开详情、Esc 关闭及拖动缩放窗口均正常，缩小后仍能到达记录末行。旧版在这轮短时人工操作中也保持响应，因此这些结果验证的是已识别的布局与失效问题，不能据此宣称完整复现或排除了所有长期卡死情形。测试使用独立资料库，未启动采集、Agent 或云端同步服务；已安装的应用未被重启或替换。

参考：[Apple 对懒栈高度估算的说明](https://developer.apple.com/videos/play/wwdc2026/321/)。该说明解释了估算机制，现场采样和本项目的对照测试才是本次修改的依据。
