# 片段显示规则与来源补全：评测记录（2026-09-24）

## 改动

| 项 | 改动前 | 改动后 |
|---|---|---|
| 片段中的引用 | 原样保留“来源：截图 `UUID`” | 去掉，ID 只在 `sourceIDs` 里给出 |
| 片段中的 Wikilink | 原样保留 `[[路径#标题\|标签]]` | 只显示标签（无标签时显示页面名） |
| 链接目标 | 只能从片段原文里解析 | 新字段 `links`：片段实际展示的行所指向的页面，`路径` 或 `路径#标题`，最多 10 个 |
| 片段长度预算 | 按原文计 300 字 | 按显示后的文字计 300 字，同样预算能放下更多事实行 |
| 页面 `source_ids` | 只用 Agent 写的列表 | 保存时把正文引用了、且有截图记录的 ID 补进来；v15 迁移对已有库补一次 |
| 引用解析 | “截图 `A`（11:19）、`B`”中两个 ID 之间带冒号的时间被当成行内代码删掉，A、B 拼在一起，两个都丢 | 行内代码从左到右成对切分，不再误删 |

二进制：`bin/myclip-mcp-links2`（轨道 B），`bin/myclip-mcp-links`（轨道 A；原始语料没有链接和引用，两者在轨道 A 上输出相同）。

- 排序不变（MRR 两个划分都相同），变化全部来自片段送达的证据：同样 300 字能放下更多事实行。
- 丢分的题：片段能放下的行变多后，按查询词得分选出的行组合变了，个别题原先展示的证据行被得分相同或更高的行替换（例如“Dance is Gina's go-to for stress relief”被同一小节的另一行替换）。逐题检查的样例中，`links` 都只含展示行的目标。
- 第一版实现（`runs/2026-09-24/links-b-*`）的 `links` 取的是展示段落里的全部链接，未展示的行也算，得分虚高（开发集 84.1%、测试集 82.5%），且与工具说明不符，已改为只取展示行，不作为结果。
